# TokenAudit 暗色控制台前端设计规范

## 1. 目标

将现有 Vue 3 + Element Plus 前端改造成一套克制、专业的暗色 Token 审计控制台，并新增应用内使用文档。

本次改造保留现有后端接口、Token 管理、审计轮询、历史记录和报告读取逻辑，重点调整：

- 全局视觉系统
- 应用框架与导航
- 各页面信息层级
- 滚动浮现和状态动效
- 响应式行为
- 应用内使用文档

最终界面应像实际安全审计工具，而不是带有超大渐变标题、营销口号和通用玻璃卡片的 AI 落地页。

## 2. 已确认的设计方向

### 2.1 视觉气质

- 采用黑绿赛博安全控制台方向。
- 主背景使用接近黑色的中性绿色调，不使用纯黑大面积死黑。
- 荧光绿仅作为功能色，用于主操作、当前导航、在线状态、进度和关键结果。
- 中文承担主要信息；英文仅用于系统状态、事件名、接口方法、终端标签和少量辅助标识。
- 使用收紧的 4–8px 圆角、细边框和低对比层级，避免大面积玻璃拟态。
- 不使用巨型营销口号、双色渐变大字、装饰性光球或无业务含义的虚构指标。

### 2.2 动效

- 动效强度为克制档。
- 页面首个内容区直接显示，后续内容区进入视口时独立浮现。
- 浮现效果由透明度、约 18–26px 上移和少量模糊消退组成。
- 同一区块内的子卡片以约 70ms 间隔错峰进入。
- 每个区块只播放一次，播放结束后保持静止。
- 在线状态可使用低频呼吸光，进度和按钮只在状态变化或交互时响应。
- 禁止持续故障闪烁、强视差和大规模粒子背景。
- 遵守 `prefers-reduced-motion`，用户要求减少动态效果时直接显示内容。

### 2.3 组件灵感与依赖原则

可借鉴组件站常见的网格背景、聚光卡片、流光边框、数字状态和终端日志形式，但使用 Vue 和 CSS 轻量实现。

不引入 React 组件库、不复制不兼容组件，也不增加 Canvas 粒子等重型运行时依赖。

## 3. 信息架构

### 3.1 主导航

桌面端保留左侧导航，顺序调整为：

1. 审计控制台
2. 发起审计
3. Token 管理
4. 历史记录
5. 使用文档

侧栏底部显示静态环境标识，例如本地模式、后端端口、Agent 数量。健康状态不能伪装成真实探测结果；如果没有健康检查结果，只显示环境信息。

窄屏下隐藏固定侧栏，改用顶部紧凑导航或可展开菜单，保证表单和表格可用。

### 3.2 路由

保留现有路由：

- `/`
- `/audit`
- `/tokens`
- `/history`
- `/report/:id`

新增：

- `/guide`

`/guide` 为应用内文档首页，内容覆盖安装、配置、录入 Token、发起审计、理解事件和阅读报告。

## 4. 页面设计

### 4.1 应用框架

- 顶部栏显示当前路径、本地环境和设置入口。
- 左侧导航使用细竖线和低对比背景表示当前页面，不使用大面积发光胶囊。
- 主内容区最大宽度约 1240–1320px。
- 背景使用低透明度细网格，不能影响正文可读性。
- Element Plus 的卡片、表格、抽屉、输入框、选择器、标签、警告和进度组件统一覆盖为暗色样式。

### 4.2 审计控制台首页

首页改为工作台，不再使用宣传式 Hero。

首屏包含：

- 小尺寸页面标题“审计控制台”
- 简短用途说明
- “新建审计”和“管理 Token”操作
- 基于现有 `listTokens()` 和 `listAudits()` 数据展示真实 Token 数量、历史审计数量和最近任务状态
- 最近审计摘要或空状态
- 审计维度概览

如果接口不可用，显示明确的不可用状态，不显示伪造数字。

### 4.3 发起审计页

保留现有审计提交、轮询、恢复最近任务和事件解释逻辑。

重新组织为：

- Token 与导出格式配置区
- 审计流水线区
- 实时进度区
- 终端式事件流

流水线必须包含代码实际执行的六个维度：

1. 有效性
2. 权限
3. 掺水/模型真实性
4. 合规
5. 稳定性
6. 安全性

综合判定作为最终汇总阶段单独展示。

### 4.4 Token 管理页

- 桌面端使用左侧新增表单、右侧 Token 列表。
- 表单字段说明采用简短辅助文字，不使用大段折叠教程占据首屏。
- Token 输入保持密码模式。
- 列表继续只显示脱敏 Token。
- 删除操作使用危险色，但控制亮度。
- 窄屏下表单和列表改为上下排列，表格允许横向滚动或使用紧凑列。

### 4.5 历史记录页

- 使用紧凑表格或任务列表展示审计 ID、Token ID、时间、状态、进度和结论。
- 状态色统一：运行中为绿色动态状态，完成为中性绿色，失败为低饱和红色。
- 空状态直接提供“发起审计”入口。

### 4.6 报告页

- 顶部先展示任务状态、综合结论和关键操作。
- 分项结果按有效性、权限、掺水、合规、稳定性、安全性排列。
- Markdown、结构化 JSON 和事件流使用明确的标签页或分区。
- JSON 与事件内容使用等宽字体，长内容允许滚动。
- 复制 Markdown 保留现有行为。
- 运行中报告继续轮询，完成或失败后停止。

### 4.7 使用文档页

采用常见 API Key 平台的开发者文档格式，而不是品牌宣传手册。

布局：

- 顶部：TokenAudit 文档标识、搜索入口、返回控制台
- 左侧：开始使用、使用指南、API 参考、帮助
- 中间：正文
- 右侧：当前页面目录

正文首页包含：

- 运行要求
- `.env` 配置
- Python、后端和前端启动方式
- Token 字段解释
- 发起审计流程
- 事件名解释
- 报告阅读顺序
- API endpoint 示例
- 密钥和本地明文存储提示

代码块支持语言/平台标签和复制按钮。搜索仅搜索内置文档标题、关键词和章节，不请求后端。

## 5. 样式系统

在 `src/styles/theme.css` 中集中定义设计变量，例如：

- 页面背景
- 面板背景
- 代码背景
- 主文本、次文本、弱文本
- 边框
- 主绿色
- 警告色
- 错误色
- 圆角
- 阴影
- 动效时长和缓动曲线

页面组件优先使用设计变量，不重复硬编码颜色。

全局样式负责：

- Element Plus 暗色变量覆盖
- 通用页面标题
- 通用面板
- 表格、表单、抽屉、弹窗和消息样式
- 滚动条
- 焦点状态
- `prefers-reduced-motion`

组件局部样式只处理具体布局。

## 6. 实现边界

### 6.1 保持不变

- 后端 API 路径和数据格式
- Axios API Key 请求头逻辑
- Token 增删行为
- 审计创建、轮询和任务恢复逻辑
- 报告获取和复制逻辑

### 6.2 允许增加

- 首页使用现有接口获取真实摘要
- `/guide` 路由和文档内容
- 前端滚动浮现指令或组合函数
- 文档本地搜索
- 必要的前端测试依赖

### 6.3 不在本次范围

- 修改 Spring Boot 或 Python 审计逻辑
- 修改数据库结构
- 实现新的后端全文搜索
- 引入第三方 CMS
- 增加主题切换；本次界面固定为暗色
- 引入重型动画、图表或粒子库

## 7. 数据与错误处理

- 首页通过现有 Token 和审计列表接口加载摘要。
- 加载期间显示低调骨架或占位，不显示虚构结果。
- API 失败时在对应区块显示错误信息和刷新操作。
- 原有 Token、审计和报告错误提示继续使用 Element Plus 消息。
- 文档搜索完全在前端内存中执行，空结果显示可恢复的提示。
- 滚动浮现不依赖业务数据；不支持 IntersectionObserver 时直接显示内容。

## 8. 响应式

关键断点：

- 约 1024px：隐藏右侧次要内容，收紧页面间距。
- 约 760px：固定侧栏切换为移动导航，多列布局改为单列。
- 小屏表格必须保持可访问，不允许内容被裁剪且无法滚动。
- 文档页在小屏隐藏左右目录，只保留正文和顶部导航。

## 9. 可访问性

- 正文和交互文本保持足够对比度。
- 绿色不能作为状态的唯一表达，同时显示文本或图形。
- 所有可点击元素必须有可见焦点。
- 动画遵守 `prefers-reduced-motion`。
- 输入框继续使用可识别标签。
- 文档导航使用真实链接和标题层级。

## 10. 测试策略

在现有前端中加入 Vitest、Vue Test Utils 和 jsdom。

测试覆盖：

- 新增 `/guide` 路由可解析。
- 滚动浮现指令在 IntersectionObserver 可用时添加可见类。
- IntersectionObserver 不可用时内容直接可见。
- 首页成功加载真实 Token/审计摘要。
- 首页接口失败时显示错误状态而不是虚构数字。
- 文档搜索可以匹配章节并处理空结果。
- 审计流水线包含安全性维度。

验证命令：

```bash
npm test
npm run build
```

完成后使用浏览器验证：

- 桌面端首页、审计、Token、历史、报告和文档页
- 移动端断点
- 滚动浮现
- `prefers-reduced-motion`
- 浏览器控制台无新增错误

## 11. 验收标准

- 所有现有功能保持可用。
- 全站呈现一致的暗色安全控制台视觉。
- 首页不再出现典型 AI 落地页的大口号和渐变大字。
- 所有主要页面区块在滚动进入视口时克制浮现。
- 新增标准 API 平台风格的使用文档。
- 文档内容能够指导用户从配置环境到读取报告。
- 桌面和移动布局均可用。
- 自动化测试和生产构建通过。
